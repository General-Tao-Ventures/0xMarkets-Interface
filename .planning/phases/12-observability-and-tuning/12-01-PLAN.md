  <behavior>
    LatencyTracker is a fixed-capacity circular buffer that stores latency measurements (numbers in milliseconds) and computes percentiles on demand.

    Constructor: `new LatencyTracker(capacity: number = 200)`

    Methods:
    - `record(latencyMs: number): void` — stores a value, overwrites oldest when full
    - `percentile(p: number): number | null` — returns value at percentile p (0-100), null if empty
    - `getPercentiles(): { p50: number | null; p95: number | null; sampleCount: number }` — convenience

    Cases:
    - Empty tracker: percentile(50) -> null, getPercentiles() -> { p50: null, p95: null, sampleCount: 0 }
    - Single value (100): percentile(50) -> 100, percentile(95) -> 100, sampleCount: 1
    - 10 values [1..10]: percentile(50) -> 5, percentile(95) -> 10, sampleCount: 10
    - 100 values [1..100]: percentile(50) -> 50, percentile(95) -> 95, sampleCount: 100
    - Overflow (capacity=5, record 1..10): buffer has [6,7,8,9,10], percentile(50) -> 8, sampleCount: 5
    - Sorted correctly for non-sequential input [500, 100, 300, 200, 400]: percentile(50) -> 300
  </behavior>
  <implementation>
    1. Create `src/test/setup.ts` as empty file (vitest.config.ts references it as setupFiles but it doesn't exist yet — vitest would error without it).

    2. Create `src/utils/latencyTracker.ts` implementing the LatencyTracker class:
       - Private `buffer: number[]` array of fixed capacity
       - Private `index: number = 0` (write cursor)
       - Private `count: number = 0` (actual filled count, max = capacity)
       - `record()`: write to buffer[index], advance index modulo capacity, increment count up to capacity
       - `percentile()`: if count === 0 return null; slice buffer to count, sort ascending, index = ceil(p/100 * length) - 1, return sorted[max(0, idx)]
       - `getPercentiles()`: calls percentile(50) and percentile(95), returns with sampleCount

    3. Create `src/utils/latencyTracker.test.ts` with tests covering all behavior cases listed above.

    Test runner command: `cd ../order-execution-keeper-service && pnpm test`
  </implementation>
</feature>
