<decisions_made>

- **Hermes HTTP over getStoredPrice**: The on-chain PythLazerFeedProvider at `0xc5810FC` doesn't have `getStoredPrice()`. Instead of deploying a new contract, switched scanner to use Pyth Hermes HTTP API (already used by candleCollector.ts for candle data). One batch HTTP call per 30s scan cycle is negligible overhead.
- **Batch price fetch at scan start**: All 7 token prices fetched in a single Hermes call at the start of each scan cycle, cached in `priceCache` Map, reused for all position evaluations.
- **Hermes feed IDs from candleCollector**: Reused the exact same Pyth Hermes feed ID mappings already defined in `candleCollector.ts`, just keyed by lowercase token address instead of symbol.
- **Price conversion formula**: `min = (price - conf) * 10^(30+expo)`, `max = (price + conf) * 10^(30+expo)` — matches how Pyth oracle providers convert to GMX's 30-decimal Price.Props format.
- **Min price floor at 1n**: Added guard for anomalous case where confidence exceeds price (would make min negative).
</decisions_made>
