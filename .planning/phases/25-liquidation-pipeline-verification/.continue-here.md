Plan 25-02 Task 2 (E2E liquidation pipeline verification) is in progress. Four bugs have been found and fixed across sessions. The latest session decoded the `0xee919dd9` error as `PositionShouldNotBeLiquidated(string,int256,int256,int256)` from DecreasePositionUtils.sol — the contract re-checks liquidatability at execution time with on-chain oracle prices and disagrees with the scanner's Hermes-based check.

Root cause identified: **price source mismatch** — scanner used Hermes HTTP prices, executor passes Lazer WebSocket bytes to contract. Different price sources produce different prices, causing borderline positions to flip between liquidatable/not-liquidatable.

Three fixes implemented and verified this session:
1. Executor bails out on gas estimation failure instead of submitting doomed TX
2. Scanner cooldown prevents re-creating candidates for failed positions (5 min)
3. Scanner now tries Lazer-derived prices first (via simulated getOraclePrice) with Hermes fallback

Also fixed: keeper-service RPC updated from public Base Sepolia to Chainstack endpoint (was rate-limiting).

The test position (50x SHORT WETH/USD) is borderline — liquidatable with Hermes but not with Lazer prices. Need a more deeply underwater position for definitive E2E test.
