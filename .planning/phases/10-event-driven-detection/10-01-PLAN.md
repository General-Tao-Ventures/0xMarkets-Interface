    **1. Create `order-execution-keeper-service/src/core/queue/executionQueue.ts`:**

    Implement an `ExecutionQueue` class with:
    - `OperationType` = `"deposit" | "withdrawal" | "order"`
    - `QueueItem` interface: `{ key: Hex; type: OperationType; detectedAt: number; source: "event" | "poll" }`
    - `pending: Map<Hex, QueueItem>` — preserves insertion order (FIFO)
    - `processing: Set<Hex>` — items currently being executed
    - `allKnown: Map<Hex, number>` — dedup across event + poll; value is enqueue timestamp
    - `enqueue(item: QueueItem): boolean` — returns false if key already in `allKnown`; adds to `allKnown` and `pending`
    - `dequeue(): QueueItem | undefined` — takes first item from `pending`, moves key to `processing`
    - `complete(key: Hex): void` — removes from `processing` (keeps in `allKnown` to prevent re-enqueue)
    - `fail(key: Hex): void` — removes from `processing` AND `allKnown` (allows re-enqueue on next scan)
    - `cleanup(): void` — removes entries from `allKnown` older than 3600 seconds (REQUEST_EXPIRATION_TIME). Called periodically.
    - `get size(): number` — returns `pending.size`
    - `get stats(): { pending: number; processing: number; known: number }` — for health/logging
    - Import `Hex` from `viem`
    - Use pino logger child `{ module: "executionQueue" }`
    - Log on enqueue (debug), dequeue (debug), complete (info with duration from detectedAt), fail (warn)

    **2. Create `order-execution-keeper-service/src/core/blockchain/abis/eventEmitter.ts`:**

    Export `eventEmitterAbi` using `parseAbi` from viem:

    ```typescript
    ]);
    ```

      2. Returns `null` if `config.wsRpcUrl` is falsy (graceful degradation)
