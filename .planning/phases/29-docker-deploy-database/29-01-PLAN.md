<task type="auto">
  <name>Task 2: Rebuild Docker containers and verify database migrations</name>
  <files></files>
  <action>
SSH to the DO server and rebuild all containers.

Step 1 -- Check existing data before rebuild (to verify DB-02 preservation):
```
cd /opt/0xmarkets
docker compose exec postgres psql -U keeper -d keeper_service -c "SELECT COUNT(*) FROM price_candles;" 2>/dev/null
docker compose exec postgres psql -U keeper -d keeper_service -c "SELECT COUNT(*) FROM position_snapshots;" 2>/dev/null
```
Record the counts (may be 0 if database is fresh, that is fine -- what matters is no data loss).

If no containers are running (docker compose exec fails), skip the pre-check -- the pgdata volume preserves data regardless.

Step 2 -- Stop and rebuild:
```
cd /opt/0xmarkets
docker compose down
docker compose up --build -d
```

The `--build` flag forces image rebuild from the updated source code. The `down` command stops containers but does NOT remove the pgdata volume (data is preserved).

Step 3 -- Wait for containers to start (keeper-service CMD runs migrations first):
Wait 30-60 seconds for builds to complete and containers to initialize. The keeper-service runs `pnpm db:migrate:deploy` before starting its process.

Step 4 -- Verify Prisma migrations applied:
```
docker compose logs keeper-service 2>&1 | grep -i "migration\|prisma\|applied"
```
Expect to see: "2 migrations found in prisma/migrations" or similar output showing migrations applied/already applied.

Step 5 -- Verify data preserved (DB-02):
```
docker compose exec postgres psql -U keeper -d keeper_service -c "SELECT COUNT(*) FROM price_candles;"
docker compose exec postgres psql -U keeper -d keeper_service -c "SELECT COUNT(*) FROM position_snapshots;"
```
Counts should be >= the pre-rebuild counts (no data loss).

If migrations fail:
- Check `docker compose logs keeper-service` for the full error
- Common fix: if the database already has tables from a non-Prisma setup, run `docker compose exec keeper-service npx prisma migrate resolve --applied 20240106000000_init` to mark the init migration as already applied

  <done>All three containers started, Prisma migrations applied (or already applied) without errors, database data counts preserved</done>
