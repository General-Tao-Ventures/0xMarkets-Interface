    **Step 2: Fix pnlUsd computation in handlePositionEvent.**

    In `src/handlers/orders.ts` `handlePositionEvent`, compute `pnlUsd` for PositionDecrease events. The formula matches GMX v2 behavior:

    For PositionDecrease: `pnlUsd = basePnlUsd - totalFees + priceImpactUsd`

    Where totalFees = positionFeeAmount + borrowingFeeAmount + fundingFeeAmount (converted to USD by multiplying by collateral token price).

    However, the simpler approach used by GMX's own subgraph is: `pnlUsd = basePnlUsd` for the TradeAction display (fees are shown separately). Check the frontend rendering code — it uses `tradeAction.pnlUsd` directly via `formatUsd(tradeAction.pnlUsd)`. In GMX's subgraph, `pnlUsd` IS set equal to `basePnlUsd` on the PositionDecrease TradeAction.

    So the fix is straightforward — add `pnlUsd` to the TradeAction in handlePositionEvent:
    ```typescript
    // In handlePositionEvent, for PositionDecrease:
    pnlUsd: getInt(data, 'basePnlUsd'),  // pnlUsd = basePnlUsd for trade history display
    ```

    Actually set pnlUsd for ALL position events (it's harmless for increases where basePnlUsd is 0):
    ```typescript
    pnlUsd: getInt(data, 'basePnlUsd'),
    ```

    Add this line to the TradeAction constructor in handlePositionEvent, alongside the existing `basePnlUsd` line.
