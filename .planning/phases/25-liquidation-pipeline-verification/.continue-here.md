## Issue 1: Lazer simulation fails with MaxPriceAgeExceeded

**Error:** `0x2b6e7c3f` = `MaxPriceAgeExceeded(uint256,uint256)`
**Location:** scanner.ts `refreshPriceCache()` line 383-388
**What happens:**
1. Scanner calls `simulateContract({ functionName: "getOraclePrice", args: [token, rawUpdate] })` on PythLazerFeedProvider (0x8a3eb351)
2. The rawUpdate bytes come from the Pyth Lazer WebSocket cache (`pythLazerOracle.getLatestUpdate()`)
3. The contract verifies the timestamp in rawUpdate against `MAX_ORACLE_PRICE_AGE` (300s = 5 min on Base Sepolia)
4. If the WS data is >300s old, the contract reverts with MaxPriceAgeExceeded
5. This causes ALL 7 tokens to fail Lazer simulation → falls back to Hermes

**Why WS data is stale:** The keeper-service may not be running, or the Pyth Lazer WebSocket connection dropped, or the binary updates stopped arriving. The scanner only reads from the cache — it doesn't check freshness before calling simulateContract.

**Fix options:**
- Option A: Check rawUpdate timestamp freshness BEFORE calling simulateContract (skip stale data, fall back to Hermes gracefully)
- Option B: Use `getStoredPrice(token)` instead of `getOraclePrice(token, rawUpdate)` — reads whatever price was last pushed on-chain (by the order-execution-keeper during its execution flow). No freshness issue since it reads stored state.
- Option C: Fix the WS connection so data is always fresh (harder, doesn't fix the Hermes fallback issue)

**Recommendation:** Option B is simplest and most reliable for the scanner. The scanner doesn't need to push prices — it just needs to READ current on-chain prices to check liquidatability. `getStoredPrice` reads whatever the order-execution-keeper last pushed.

## Issue 2: Hermes fallback price precision MAY be wrong

**Symptom:** remainingCollateralUsd = ~4.6 BILLION for a $63 collateral position
**Location:** scanner.ts `refreshPriceCache()` lines 413-427
**Hermes conversion code:**
```typescript
const p = BigInt(priceData.price.price);
const c = BigInt(priceData.price.conf);
const expo = priceData.price.expo;
const gmxExponent = 30 + expo;
// scale = 10^gmxExponent
// min = (p - c) * scale
```

**Analysis:** The math for converting Pyth Hermes prices to GMX 30-decimal format LOOKS correct at first glance. However, GMX Reader.isPositionLiquidatable may expect prices in a DIFFERENT precision than "USD per whole token * 10^30". Need to verify by comparing:
1. What `getOraclePrice` / `getStoredPrice` actually returns for a known token (e.g., WETH)
2. What the Hermes conversion produces for the same token
3. If they differ → the Hermes conversion has a precision mismatch

**If Issue 1 is fixed (use getStoredPrice), Issue 2 becomes moot** — scanner would use on-chain prices directly, never touching Hermes at all.

## Simplest fix: Replace Lazer simulation with getStoredPrice

In scanner.ts `refreshPriceCache()`, replace the entire Lazer simulation block AND Hermes fallback with a simple `getStoredPrice(token)` call:

```typescript
// For each token, read the last stored price from PythLazerFeedProvider
const result = await publicClient.readContract({
    address: PYTH_LAZER_FEED_PROVIDER_ADDRESS,
    abi: pythLazerFeedProviderAbi,  // already defined in contract.ts
    functionName: "getStoredPrice",
    args: [tokenAddress],
});
// result = [ok: boolean, (token, min, max, timestamp, provider)]
if (result[0]) {
    priceCache.set(tokenKey, { min: result[1][1], max: result[1][2] });
}
```

**Why this works:**
- The order-execution-keeper pushes Lazer prices on-chain before every execution via `updatePrice()`
- Prices stay in the PythLazerFeedProvider contract storage
- `getStoredPrice` reads these stored prices — no freshness check, no WS dependency
- The prices are in EXACTLY the format Reader.isPositionLiquidatable expects (same contract wrote them)
- No Hermes fallback needed at all

**Caveat:** Stored prices go stale if the order-execution-keeper hasn't pushed recently. But for liquidation scanning, slightly stale prices are OK — the executor will push fresh prices before the actual liquidation TX.

**ABI already exists in contract.ts line 14-16:**
```typescript
export const pythLazerFeedProviderAbi = parseAbi([
    "function getStoredPrice(address token) view returns (bool, (address, uint256, uint256, uint256, address))",
]);
```
