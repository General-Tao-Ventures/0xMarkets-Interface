  <name>Task 2: Add revert tracking to executor via receipt watcher</name>
  <files>keeper-service/src/core/executor.ts</files>
  <action>
Add a non-blocking receipt watcher to the executor that polls for transaction receipts after submission and updates the database if the TX reverted.

1. Import `Hex` from viem (already imported), ensure `publicClient` is imported from contract.ts (already imported).

2. Add a private `watchReceipt` method to the `Executor` class:
```typescript
private async watchReceipt(executionId: string, txHash: Hex, candidateId: string): Promise<void>
```

3. Inside `watchReceipt`:
   - Call `publicClient.waitForTransactionReceipt({ hash: txHash, timeout: 120_000 })` (2-minute timeout).
   - IMPORTANT: `waitForTransactionReceipt` does NOT throw on reverts in viem v2. It returns the receipt with `status: 'reverted'`. Must explicitly check `receipt.status`.
   - If `receipt.status === 'reverted'`:
     - Set reason to `"Transaction reverted at block ${receipt.blockNumber}"`. Do NOT over-engineer revert reason extraction (it requires debug_traceTransaction which is unreliable).
     - Call `store.updateExecutionStatus(executionId, "REVERTED", undefined, reason)`.
     - Call `store.updateCandidateStatus(candidateId, "FAILED")`.
     - Log warn with `{ executionId, txHash, reason }`.
   - If `receipt.status === 'success'`: do nothing (confirmator handles MINED status via OrderExecuted events).
   - Catch `WaitForTransactionReceiptTimeoutError`: log warn but do NOT update status (let stuck detection handle this in a future phase).
   - Catch other errors: log error and rethrow.

4. In the `execute()` method, after `store.createExecution()` and `store.updateCandidateStatus(candidate.id, "PENDING")` (around line 219), add a fire-and-forget call to `watchReceipt`:
```typescript
this.watchReceipt(executionId, hash, candidate.id).catch(err => {
    log.error({ err, executionId, txHash: hash }, "receipt watcher failed");
});
```

IMPORTANT: Do NOT `await` the watchReceipt call. It must be fire-and-forget so the executor can continue processing other candidates. The `.catch()` prevents unhandled promise rejections.
