   ```typescript
   const symbol = symbolInfo.name;
   const visualMultiplier = parseInt(symbolInfo.unit_id ?? "1");

   // Track last bar time for candle period detection
   let lastBarTime = 0;

   const handler = (candles: CandleData[]) => {
     const candle = candles.find(c => c.tokenSymbol === symbol);
     if (!candle) return;

     const bar: Bar = {
       time: candle.minuteTs,
       open: candle.open,
       high: candle.high,
       low: candle.low,
       close: candle.close,
     };

     // If new candle period and we have a previous bar, patch previous bar's close
     if (lastBarTime > 0 && candle.minuteTs > lastBarTime) {
       // New minute started -- the previous bar's close should match this bar's open
       // TradingView handles this naturally when receiving a bar with a new time
     }

     lastBarTime = candle.minuteTs;
     onTick(multiplyBarValues(formatTimeInBarToMs(bar), visualMultiplier));
   };

   this.wsManager.on("candle", handler);
   this.subscriptions[listenerGuid] = {
     destroy: () => this.wsManager.off("candle", handler),
   };
   ```

5. Keep the PauseableInterval as FALLBACK for: (a) V1 trade page, (b) stable tokens, (c) when `this.wsManager.getState() !== "connected"` at subscription time. Actually -- simpler approach: always register the WS handler for V2 non-stable tokens. The PauseableInterval fallback is complex to maintain here. Instead, if WS disconnects, the `useTokenRecentPricesData` adaptive polling handles price updates, and users can use chart zoom/scroll to trigger `getBars` which fetches HTTP candles. The 200ms WS candle updates will resume on reconnect.

6. In `destroy()`, the existing cleanup loop already calls `destroy()` on each subscription, which now correctly calls `wsManager.off()` for WS subscriptions.

7. For `pauseAll`/`resumeAll` (visibility changes): These called `.pause()` and `.resume()` on PauseableInterval. For WS subscriptions, pausing is unnecessary -- the WS manager stays connected and the `onTick` calls are cheap. Add a type guard: only call pause/resume if the subscription has those methods.
   ```typescript
   private pauseAll() {
     Object.values(this.subscriptions).forEach((sub) => {
       if ('pause' in sub) (sub as PauseableInterval<any>).pause();
     });
   }
   private resumeAll() {
     Object.values(this.subscriptions).forEach((sub) => {
       if ('resume' in sub) (sub as PauseableInterval<any>).resume();
     });
   }
   ```

IMPORTANT: The keeper broadcasts 1-minute candles. OHLC for aggregated resolutions comes from the initial `getBars` HTTP fetch. This matches the existing behavior where subscribeBars fetched 1 candle at a time and TradingView updated the current bar.
