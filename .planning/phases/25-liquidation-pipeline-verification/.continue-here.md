## Fix executeLiquidation contract revert
The `0xee919dd9` error signature needs to be decoded. Likely causes:
1. **Stale oracle prices**: The Lazer WebSocket data passed in oracleParams may be rejected by PythLazerFeedProvider. The order-execution-keeper IS running and pushing prices, but the Lazer update bytes in the executor's oracle params may be stale by the time the liquidation TX is submitted.
2. **Position no longer liquidatable**: Between scanner detection and executor submission (~200ms), prices may have shifted enough that the position is no longer liquidatable at execution time.
3. **Oracle data format issue**: The executor passes raw Lazer WebSocket bytes — verify these are accepted by the contract.

Approach to debug:
- Decode `0xee919dd9` error signature (check https://openchain.xyz/signatures?query=0xee919dd9 or search contract ABIs)
- Try passing `0x` as oracle data (fallback to stored prices) instead of Lazer bytes
- Check if the contract's `executeLiquidation` requires the position to still be liquidatable at execution time with the provided prices
