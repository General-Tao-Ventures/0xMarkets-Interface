<objective>
Create the event indexer loop that subscribes to the EventEmitter contract via WebSocket, decodes incoming events using the decoder (Phase 32-01), routes them to insert handlers (Phase 32-02), and persists a block cursor for crash recovery.

Purpose: This is the runtime loop that connects the decoder/router pipeline to live on-chain data. Without it, the event tables remain empty. The cursor-based recovery ensures no events are lost across service restarts.

Output: A working event indexer collector wired into the service lifecycle, with historical replay on startup and real-time WebSocket subscription.
</objective>

**eventIndexer.ts** — Create the event indexer collector following the same pattern as `marketSnapshotter.ts`:

The module exports: `startEventIndexer`, `stopEventIndexer`, `getLastIndexedBlock`, `getIndexedEventCount`.

**Architecture:**

1. **Cursor management** (pg Client):
   - `readCursor()`: `SELECT last_block FROM event_cursor WHERE collector_type = 'event_indexer'` — returns bigint
   - `writeCursor(blockNumber)`: `UPDATE event_cursor SET last_block = $1, updated_at = NOW() WHERE collector_type = 'event_indexer'`

2. **Historical replay** (`replayFromCursor`):
   - Called on startup before real-time subscription begins
   - Reads cursor from DB
   - If cursor is 0, set cursor to current block number (no historical replay on first run — backfill is a future feature, BACKFILL-01/02)
   - If cursor > 0, fetch logs from `cursor + 1` to current head using `publicClient.getLogs()` in chunks of 2000 blocks (RPC limits)
   - For each chunk: fetch logs filtered by EventEmitter address and topic0 in [EVENT_LOG1_TOPIC, EVENT_LOG2_TOPIC]
   - For each log in chunk: get block timestamp via `publicClient.getBlock({ blockNumber })` (cache block timestamps within a chunk to avoid redundant RPC calls — multiple logs in same block share timestamp)
   - Decode each log with `decodeEventLog(log.topics, log.data, isEventLog2)` where `isEventLog2 = log.topics[0] === EVENT_LOG2_TOPIC`
   - Build LogMeta: `{ blockNumber: log.blockNumber, logIndex: log.logIndex, transactionHash: log.transactionHash, blockTimestamp }`
   - Route each decoded event with `routeEvent(pgClient, decoded, meta)`
   - After each chunk completes, update cursor to the highest block number in the chunk
   - Log progress: `"replayed historical events"` with `{ fromBlock, toBlock, eventCount }`

3. **Real-time subscription** (`startRealtime`):
   - Create a WebSocket-backed viem public client: `createPublicClient({ chain: baseSepolia, transport: webSocket(config.wsRpcUrl) })`
   - viem's WebSocket transport auto-reconnects on disconnection (LIST-02) — no custom reconnect logic needed
   - Use `wsClient.watchBlockNumber({ onBlockNumber })` to detect new blocks
   - On each new block number, if it's greater than `lastProcessedBlock`:
     - Fetch logs for the range `lastProcessedBlock + 1` to `blockNumber` using `wsClient.getLogs()` with same filters
     - This batch approach (not per-log subscription) ensures we don't miss logs when blocks arrive quickly
     - For each log: decode, build meta (get block timestamp), route to handler
     - After all logs processed, update cursor
     - Update `lastProcessedBlock` in memory
   - `onError`: log the error at ERROR level — viem reconnects automatically

4. **State tracking:**
   - `let lastProcessedBlock: bigint = 0n` — tracks cursor in memory
   - `let indexedEventCount = 0` — running count of events indexed this session
   - `let unwatch: (() => void) | null = null` — cleanup function from watchBlockNumber

5. **Error handling per-event:**
   - If `routeEvent` throws for a single event, log error with `{ eventName, blockNumber, logIndex }` and CONTINUE to next event — don't crash the indexer
   - This is important: one bad event shouldn't halt processing of the entire block's events
   - The ON CONFLICT DO NOTHING in handlers already prevents duplicate inserts from retries

6. **Block timestamp caching:**
   - During both replay and real-time, cache block timestamps: `Map<bigint, bigint>` keyed by block number
   - Clear cache after each chunk/batch to avoid memory growth
   - This is important because a single block can emit dozens of events, and we don't want to call `getBlock` for each log

7. **pg Client lifecycle:**
   - Create a dedicated pg Client in `startEventIndexer` (separate from migrate.ts client)
   - Keep it connected for the lifetime of the indexer (cursor reads/writes + event inserts share it)
   - Close it in `stopEventIndexer`

**Function signatures:**

```typescript
export async function startEventIndexer(publicClient: PublicClient): Promise<void>
// publicClient is the HTTP-based client from index.ts (used for getBlock during replay)
// Creates its own WebSocket client for real-time subscription

export function stopEventIndexer(): void

export function getLastIndexedBlock(): bigint

export function getIndexedEventCount(): number
```

**IMPORTANT**: The `startEventIndexer` function is async because it needs to:
1. Connect the pg Client
2. Read cursor from DB
3. Complete historical replay
4. Only then start real-time subscription

This differs from `startMarketSnapshotter` which is synchronous (just calls watchBlocks). The index.ts caller must `await startEventIndexer(...)`.
