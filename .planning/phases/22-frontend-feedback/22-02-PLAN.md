  <action>
  **Add SWR global mutate to SyntheticsEventsProvider:**

  1. Import `useSWRConfig` from "swr" at top of SyntheticsEventsProvider.tsx
  2. Inside the SyntheticsEventsProvider component, destructure `mutate` from `useSWRConfig()`:
     ```typescript
     const { mutate: globalMutate } = useSWRConfig();
     ```

  3. Create a debounced refresh helper using `useRef` and `useCallback`:
     ```typescript
     const refreshTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

     const triggerDataRefresh = useCallback(() => {
       // Debounce: if a refresh is already scheduled, skip
       if (refreshTimerRef.current) return;

       refreshTimerRef.current = setTimeout(() => {
         refreshTimerRef.current = null;
         // Revalidate market tokens data (GM balances for pools page)
         globalMutate(
           (key: unknown) => Array.isArray(key) && key[1] === "useMarketTokensData",
           undefined,
           { revalidate: true }
         );
         // Revalidate positions data (for trade page)
         globalMutate(
           (key: unknown) => Array.isArray(key) && key[1] === "usePositionsData",
           undefined,
           { revalidate: true }
         );
         // Revalidate token balances (wallet USDC, GM tokens)
         globalMutate(
           (key: unknown) => Array.isArray(key) && key[1] === "useTokenBalances",
           undefined,
           { revalidate: true }
         );
       }, 300); // 300ms debounce -- batches rapid events
     }, [globalMutate]);
     ```

  4. Add `triggerDataRefresh()` call in each execution/cancellation handler, right after the existing status update calls:

     **Deposit events (add triggerDataRefresh after setDepositStatuses):**
     - `DepositExecuted` handler: add `triggerDataRefresh();` after `setDepositStatuses(...)`
     - `DepositCancelled` handler: add `triggerDataRefresh();` after `setDepositStatuses(...)`
     - `GlvDepositExecuted` handler: add `triggerDataRefresh();` after `setDepositStatuses(...)`
     - `GlvDepositCancelled` handler: add `triggerDataRefresh();` after `setDepositStatuses(...)`

     **Withdrawal events (add triggerDataRefresh after setWithdrawalStatuses):**
     - `WithdrawalExecuted` handler: add `triggerDataRefresh();` after `setWithdrawalStatuses(...)`
     - `WithdrawalCancelled` handler: add `triggerDataRefresh();` after `setWithdrawalStatuses(...)`
     - `GlvWithdrawalExecuted` handler: add `triggerDataRefresh();` after `setWithdrawalStatuses(...)`
     - `GlvWithdrawalCancelled` handler: add `triggerDataRefresh();` after `setWithdrawalStatuses(...)`

     **Order events (add triggerDataRefresh after setOrderStatuses):**
     - `OrderExecuted` handler: add `triggerDataRefresh();` after `setOrderStatuses(...)`
     - `OrderCancelled` handler: add `triggerDataRefresh();` after `setOrderStatuses(...)`

  5. Add cleanup in a useEffect to clear the timer on unmount:
     ```typescript
     useEffect(() => {
       return () => {
         if (refreshTimerRef.current) clearTimeout(refreshTimerRef.current);
       };
     }, []);
     ```

  **IMPORTANT:** The `eventLogHandlers.current = { ... }` object is reassigned on every render (not wrapped in useMemo/useCallback). This means `triggerDataRefresh` can be called directly inside handler bodies without needing to be in the dependency array of anything -- it's always fresh since the handlers object is recreated each render.

  **NOTE on SWR key matching:** The key matcher function receives the full SWR key. For multicall hooks, keys are arrays like `[chainId, "useMarketTokensData", ...]`. The `key[1]` check matches the hook name. Use `"useTokenBalances"` for token balance data -- check the actual key name used in `useTokensDataRequest` or equivalent hook. Verify by searching: `grep -rn "useTokenBalances\|useTokensData" src/domain/synthetics/tokens/` to find the exact SWR key name used.
