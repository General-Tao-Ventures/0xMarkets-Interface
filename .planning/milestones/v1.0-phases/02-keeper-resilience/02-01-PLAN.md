**New `execute()` method** (replaces current `execute`):
- For loop from attempt 1 to MAX_RETRIES
- Calls `executeOnce(key, attempt)` in try/catch
- On catch: check `isPermanentError(error)` and `isLastAttempt`
  - If permanent OR last attempt: call `recordFailure(key, error, attempt)`, then throw
  - If transient and not last: log warning with attempt number, compute backoff as `BASE_BACKOFF_MS * Math.pow(2, attempt - 1)`, await setTimeout, continue loop
- DB status stays PENDING during retries (critical — see Pitfall 1 in research)

**New `executeOnce()` private method:**
- Move ALL current `execute()` body here (the try block contents, lines 16-180 of current file)
- Add `attempt: number` parameter for logging
- The catch block at the end should NOT set FAILED — that is now handled by `recordFailure` in the retry wrapper
- Instead, catch block should just log and re-throw (the outer retry loop handles status)
- IMPORTANT: Keep the CANCELLED status writes for ghost/stale deposits inside `executeOnce` — those are not retryable and should return early (not throw)

**New `isPermanentError()` private method:**
```typescript
private isPermanentError(error: unknown): boolean {
  const msg = error instanceof Error ? error.message : String(error);
  const lower = msg.toLowerCase();
  // Contract-level errors: deposit already consumed, expired, malformed
  if (msg.includes('0x95b66fe9')) return true; // EmptyDeposit() selector
  if (lower.includes('oracletimestampsarelargerthanrequestexpirationtime')) return true;
  if (lower.includes('no tokens to price')) return true;
  // Gas estimation failures that indicate contract revert (not transient gas spike)
  if (lower.includes('execution reverted')) return true;
  return false;
}
```

**New `isTransientError()` private method:**
```typescript
private isTransientError(error: unknown): boolean {
  if (this.isPermanentError(error)) return false;
  const msg = error instanceof Error ? error.message : String(error);
  const lower = msg.toLowerCase();
  return (
    lower.includes('timeout') ||
    lower.includes('network') ||
    lower.includes('fetch failed') ||
    lower.includes('nonce too low') ||
    lower.includes('replacement transaction underpriced') ||
    lower.includes('econnreset') ||
    lower.includes('etimedout') ||
    lower.includes('intrinsic gas too low')
  );
}
```

Note: If an error is neither permanent nor transient (unknown category), the retry loop should still retry (treat unknown errors as potentially transient). The `isTransientError` check is used for logging clarity, but the retry decision is: "if NOT permanent AND NOT last attempt, retry".

**New `recordFailure()` private method:**
```typescript
private async recordFailure(key: Hex, error: unknown, attempts: number): Promise<void> {
  const prisma = await getOrCreatePrismaClient();
  const reason = (error instanceof Error ? error.message : String(error)).slice(0, 500);
  const current = await prisma.depositRequest.findUnique({
    where: { requestKey: key },
    select: { status: true },
  });
  if (current?.status === 'PENDING') {
    await prisma.depositRequest.update({
      where: { requestKey: key },
      data: {
        status: 'FAILED',
        errorReason: reason,
        retryCount: attempts,
      },
    });
  }
}
```
