    - `getWsPublicClient, getPublicClient` from `../blockchain/client.js`
    - `eventEmitterAbi` from `../blockchain/abis/eventEmitter.js`

    - `config` from `../../config.js`
    - `logger` from `../../utils/logger.js`
    - `store` from `../store.js` (for Prisma access to KeeperState)
    - `setWsStatus` from `../../utils/healthState.js` (to be added in Task 3)

    **Constants:**
    - `DEPOSIT_CREATED = "DepositCreated"`
    - `WITHDRAWAL_CREATED = "WithdrawalCreated"`
    - `ORDER_CREATED = "OrderCreated"`
    - Map event names to OperationType: `{ DepositCreated: "deposit", WithdrawalCreated: "withdrawal", OrderCreated: "order" }`
    - Compute event name hashes for topic filtering:
      ```typescript
      const EVENT_NAMES = [DEPOSIT_CREATED, WITHDRAWAL_CREATED, ORDER_CREATED] as const;
      ```

    **Class: EventListener**
    Constructor takes `queue: ExecutionQueue`.

    **`async start(): Promise<void>`:**
    1. Run `await this.backfillFromLastBlock()` first (DETECT-03: recover missed events)
    2. Get WebSocket client via `getWsPublicClient()`. If null, log warning "No WebSocket client — using polling fallback only" and return
    3. Watch BOTH `EventLog1` AND `EventLog2` events on the EventEmitter contract address (`config.eventEmitterAddress`). Per research, `DepositCreated`/`WithdrawalCreated`/`OrderCreated` use `EventLog2`, but watch both for safety.
    4. Use `wsClient.watchContractEvent({ address, abi: eventEmitterAbi, eventName: "EventLog2", onLogs: this.handleLogs.bind(this), onError: this.handleError.bind(this) })`. Store the returned `unwatch` function.
    5. Also watch `EventLog1` with the same handler pattern. Store its `unwatch`.
    6. Call `setWsStatus(true)` on successful start
    7. Log info: "EventListener started, watching EventEmitter at {address}"

    **`private handleLogs(logs: Log[]): void`:**
    1. For each log, decode using `decodeEventLog({ abi: eventEmitterAbi, data: log.data, topics: log.topics })`
    2. Extract `eventName` from decoded args (the string field, not the hash)
    3. Check if `eventName` is one of the three creation events. If not, skip.
    4. Extract the request key from `args.topic1` (bytes32 — this is the deposit/withdrawal/order key)
    5. Map eventName to OperationType using the constant map
    6. Call `this.queue.enqueue({ key, type, detectedAt: Date.now(), source: "event" })`
    7. If enqueue returns true, log info with `{ eventName, key, blockNumber: log.blockNumber }`: "detected {eventName} via event"
    8. Update `lastProcessedBlock` in memory (don't persist every event — persist periodically)
    9. Persist block number to DB every 10 events or when block number advances by 5+ blocks: `await this.persistBlock(log.blockNumber)`

    **`private handleError(error: Error): void`:**
    1. Log error: "WebSocket event listener error"
    2. Call `setWsStatus(false)`
    3. The viem WebSocket transport has built-in reconnect (configured in client.ts with `maxAttempts: Infinity, delay: 2_000`). On reconnect, `watchContractEvent` resumes automatically.
    4. Schedule a backfill after a brief delay (5 seconds) to catch any events missed during the disconnect: `setTimeout(() => this.backfillFromLastBlock().catch(err => log.error({ err }, "backfill after reconnect failed")), 5_000)`
    5. Re-set `setWsStatus(true)` after successful backfill (inside the backfill method)

    **`async backfillFromLastBlock(): Promise<void>` (DETECT-03):**
    1. Read `lastProcessedBlock` from Prisma KeeperState: `const state = await store.prisma.keeperState.findUnique({ where: { id: "singleton" } })`
    2. If no state exists, create one with current block number: `const currentBlock = await getPublicClient().getBlockNumber(); await store.prisma.keeperState.create({ data: { id: "singleton", lastProcessedBlock: currentBlock } }); return;`
    3. Get current block from HTTP client: `const currentBlock = await getPublicClient().getBlockNumber()`
    4. If `fromBlock >= currentBlock`, return (no gap)
    5. Use `getPublicClient().getLogs({ address: config.eventEmitterAddress, fromBlock: state.lastProcessedBlock + 1n, toBlock: currentBlock })` to fetch all EventEmitter logs
    6. For each log, decode and check if it's a creation event (same logic as handleLogs)
    7. Enqueue any found events
    8. Persist `currentBlock` as the new `lastProcessedBlock`
    9. Log info: "backfill complete, processed {count} events from block {from} to {to}"
    10. Call `setWsStatus(true)` if WebSocket client exists

    **`private async persistBlock(blockNumber: bigint): Promise<void>`:**
    1. Upsert KeeperState: `await store.prisma.keeperState.upsert({ where: { id: "singleton" }, update: { lastProcessedBlock: blockNumber }, create: { id: "singleton", lastProcessedBlock: blockNumber } })`

    **`async stop(): Promise<void>`:**
    1. Call stored `unwatch` functions for both EventLog1 and EventLog2
    2. Call `setWsStatus(false)`
    3. Persist the last known block number
    4. Log info: "EventListener stopped"

    **CRITICAL per research:**
    - Do NOT call executors directly from event callbacks. Only enqueue.
    - The `eventName` string field (non-indexed) in the log args is the human-readable event name. Use this to classify events.
    - The `topic1` arg in EventLog2 is the request key (bytes32).
    - The `eventNameHash` is the indexed keccak256 of the event name — used for filtering but `eventName` string is more reliable for classification.

    ```typescript
    async function scanAndEnqueue(): Promise<void> {
      try {
        if (config.enableDeposits) {
          const result = await depositScanner.scan();
          for (const key of result.depositKeys) {
            queue.enqueue({ key, type: "deposit", detectedAt: Date.now(), source: "poll" });
          }
        }
        if (config.enableWithdrawals) {
          const result = await withdrawalScanner.scan();
          for (const key of result.withdrawalKeys) {
            queue.enqueue({ key, type: "withdrawal", detectedAt: Date.now(), source: "poll" });
          }
        }
        if (config.enableOrders) {
          const result = await orderScanner.scan();
          for (const key of result.orderKeys) {
            queue.enqueue({ key, type: "order", detectedAt: Date.now(), source: "poll" });
          }
        }
        recordScanCycle();
      } catch (error) {
        logger.error({ err: error }, "scan cycle failed");
      }
    }
    ```

    **New `drainQueue()` function:**
    This is the single-consumer loop. It runs forever, pulling items from the queue one at a time.
    ```typescript
    async function drainQueue(): Promise<void> {
      const log = logger.child({ module: "queueConsumer" });
      while (!shuttingDown) {
        const item = queue.dequeue();
        if (!item) {
          await new Promise(r => setTimeout(r, 100)); // idle wait
          continue;
        }
        try {
          if (item.type === "deposit" && config.enableDeposits) {
            await depositExecutor.execute(item.key);
          } else if (item.type === "withdrawal" && config.enableWithdrawals) {
            await withdrawalExecutor.execute(item.key);
          } else if (item.type === "order" && config.enableOrders) {
            await orderExecutor.execute(item.key);
          }
          queue.complete(item.key);
          recordExecution(item.type);
          const latencyMs = Date.now() - item.detectedAt;
          log.info({ key: item.key, type: item.type, source: item.source, latencyMs }, "execution complete");
        } catch (error) {
          queue.fail(item.key); // allow re-enqueue on next scan
          log.error({ err: error, key: item.key, type: item.type }, "execution failed");
        }
      }
    }
    ```
