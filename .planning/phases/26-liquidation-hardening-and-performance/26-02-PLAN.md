<objective>
Add performance optimizations and observability instrumentation to the liquidation pipeline: multicall batching for position discovery, position data reuse to eliminate redundant RPC calls, and per-stage timing logs.

Purpose: Without multicall, position discovery makes N serial RPC calls (one per position key). Without data reuse, the executor re-fetches position data that the scanner already has. Without timing instrumentation, there is no visibility into pipeline performance.
Output: Faster position discovery via multicall, eliminated redundant RPC call in executor, and structured timing logs across all pipeline stages.
</objective>

**positionFetcher.ts -- Multicall batching (LPERF-01):**

Replace the serial `getPosition()` loop in `discoverAccountsWithPositions()` (lines 249-262) with a single `publicClient.multicall()` call per batch.

1. Import `publicClient` from `./contract.js` if not already imported at top level (it IS already imported).
2. In `discoverAccountsWithPositions()`, after getting the `positionKeys` array from `getBytes32ValuesAt`, instead of the for loop that calls `readContract` per key, do:

```typescript
// MULTICALL: batch all getPosition calls into one RPC request
const contracts = positionKeys.map(key => ({
    address: READER_ADDRESS as Address,
    abi: READER_ABI,
    functionName: "getPosition" as const,
    args: [DATA_STORE_ADDRESS, key] as const,
}));

const results = await publicClient.multicall({
    contracts,
    allowFailure: true, // Individual positions can fail without breaking batch
});

for (let i = 0; i < results.length; i++) {
    const result = results[i];
    if (result.status === "success" && result.result) {
        const position = result.result as PositionProps;
        if (position.numbers.sizeInUsd > 0n) {
            accounts.add(position.addresses.account);
        }
    } else {
        log.warn({ positionKey: positionKeys[i] }, "failed to fetch position in multicall");
    }
}
```

IMPORTANT: Use `allowFailure: true` so a single bad position key does not break the entire batch. Keep the existing `batchSize = 100` loop -- each batch of 100 position keys becomes one multicall.

NOTE: `READER_ADDRESS` and `READER_ABI` are already imported from `./contract.js` at the top. The local `const READER_ABI = Reader_abi;` line can stay since it aliases the same value. Use the local `READER_ABI` for the multicall contracts array.

**executor.ts -- Position data reuse (LPERF-02):**

The executor currently re-fetches position data on line 129 via `positionFetcher.fetchPositionByKey()` just to get `collateralToken` and `isLong`. But these are already on the PositionSnapshot that the scanner created. The problem: `store.getPositionSnapshotById()` does NOT return `collateralToken` or `isLong` because they are not persisted to the DB.

Use the in-memory approach (recommended by research): pass `collateralToken` and `isLong` directly through the candidate pipeline since scanner calls executor synchronously.

1. Update the `execute()` method signature to accept optional `collateralToken` and `isLong` parameters:
```typescript
async execute(
    candidate: LiquidationCandidate,
    decision: SignedDecisionRecord,
    positionData?: { collateralToken: Address; isLong: boolean }
): Promise<void>
```

2. In the `execute()` method body, replace the positionKey-based lookup block (lines 123-142) with:
```typescript
let collateralToken: Address;
let isLong: boolean;

if (positionData) {
    // Use data passed from scanner (no RPC call needed)
    collateralToken = positionData.collateralToken;
    isLong = positionData.isLong;
} else if (positionSnapshot.positionKey) {
    // Fallback: fetch from chain (for cases where executor is called independently)
    const position = await positionFetcher.fetchPositionByKey(positionSnapshot.positionKey);
    if (position?.collateralToken && position.isLong !== undefined) {
        collateralToken = position.collateralToken;
        isLong = position.isLong;
    } else {
        log.error({ candidateId: candidate.id, positionKey: positionSnapshot.positionKey }, "position not found by key on-chain");
        await store.updateCandidateStatus(candidate.id, "FAILED");
        return;
    }
} else {
    log.error({ candidateId: candidate.id }, "no position data and no positionKey");
    await store.updateCandidateStatus(candidate.id, "FAILED");
    return;
}
```

3. Remove the `positionFetcher` import if it is no longer used elsewhere in the file. Check: `buildOracleParams` does NOT use positionFetcher, and `watchReceipt` (from Plan 01) does not either. So the import can be removed. BUT keep it as a safety fallback in case executor is ever called without positionData.
