  <action>
    Fix the deposit executor to properly handle stale/ghost deposit keys and ensure oracle parameters are always valid before calling executeDeposit.

    **In depositExecutor.ts:**

    1. **Guard against zeroed-out deposits (EmptyDeposit prevention):**
       - After fetching the deposit via `Reader.getDeposit(key)`, check if the deposit's account address is the zero address (`0x0000000000000000000000000000000000000000`). This means the deposit struct has been deleted on-chain (ghost key).
       - If the deposit is null or zeroed out, mark the DB record as `CANCELLED` (NOT `FAILED` — per research anti-pattern guidance, this is not an execution failure, it's a stale ghost key).
       - Log a clear message: `Deposit ${key} is stale (zeroed on-chain) — marking CANCELLED`
       - Return early, do not attempt gas estimation or execution.

    2. **Ensure oracle tokens are non-empty before building oracle params:**
       - After building the token set for oracle pricing (index token + long/short tokens), validate the array is non-empty.
       - If `tokensToPrice` is empty, log an error and mark the deposit as FAILED with reason "No tokens to price — deposit may be malformed".
       - Do NOT proceed to `buildOracleParams` with an empty token list.

    3. **Add detailed success logging (per user decision):**
       - After successful execution (tx receipt confirmed), log:
         - Tx hash of the executeDeposit transaction
         - GM tokens minted (if available from events or by reading balance diff)
         - Time from detection to completion (add a `startTime = Date.now()` at the start of `execute()`)
       - Format: `Deposit ${key} executed successfully: txHash=${hash}, duration=${seconds}s`

    **In baseExecutor.ts:**

    4. **Guard buildOracleParams against empty tokens:**
       - At the start of `buildOracleParams`, if the `tokens` array is empty, throw an explicit error: `Cannot build oracle params: no tokens to price`
       - This prevents the silent `{tokens:[], providers:[], data:[]}` return that causes downstream contract reverts.

    5. **WebSocket disconnect handling (Claude's discretion — pick safer option):**
       - In the oracle update path, if `updatePriceOnChain` fails because the WebSocket is disconnected AND the cached update is stale (>30s), throw an error for that individual deposit execution.
       - Do NOT crash the entire keeper process. The scanner should keep running so the next 10s cycle can retry if the WebSocket recovers.
       - Log: `Oracle price update failed for ${token} — WebSocket disconnected and cache stale. Will retry next cycle.`
  </action>
