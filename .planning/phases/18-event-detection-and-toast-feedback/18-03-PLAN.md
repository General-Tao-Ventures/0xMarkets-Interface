This task fixes the root cause of UAT gap 3: the useEffect dependency array includes `depositStatuses`, `withdrawalStatuses`, and `orderStatuses` state objects which cause the interval to tear down and restart on every status change, even though the values are read through refs.

**In `src/context/SyntheticsEvents/useExecutionPolling.ts`:**

Change the useEffect dependency array (lines 311-321) from:
```typescript
}, [
  depositStatuses,
  withdrawalStatuses,
  orderStatuses,
  watchedTxnHashes,
  chainId,
  setDepositStatuses,
  setWithdrawalStatuses,
  setOrderStatuses,
  setWatchedTxnHashes,
]);
```
to:
```typescript
// eslint-disable-next-line react-hooks/exhaustive-deps
}, [
  watchedTxnHashes,
  chainId,
  setDepositStatuses,
  setWithdrawalStatuses,
  setOrderStatuses,
  setWatchedTxnHashes,
]);
```

Remove `depositStatuses`, `withdrawalStatuses`, and `orderStatuses` from the dependency array. These are already read via refs (`depositStatusesRef.current`, etc.) inside the poll function. Including them in deps causes the effect to tear down the `setInterval` and recreate it on every status change, which means:
- Phase A processes a receipt and fires event handlers (setting status)
- Status update triggers re-render
- Re-render causes effect cleanup (clears interval)
- Effect re-runs, starts new interval
- New interval starts fresh (no continuity)
- This cycle repeats, preventing stable polling

With the fix, the interval remains stable. Status changes are picked up via refs on the next poll cycle (3 seconds). The interval only recreates when `watchedTxnHashes` changes (new hashes added/removed) or `chainId` changes, which is the correct behavior.

Keep the existing `// eslint-disable-next-line react-hooks/exhaustive-deps` comment that is already on line 310. The lint suppression is correct because we intentionally read status objects through refs to avoid recreating the interval.

**Also update the `hasPendingOps` check at the top of the effect** (line 109-112) to also check watchedTxnHashes via refs instead of the direct state value on line 114:

Change line 114 from:
```typescript
const hasWatchedTxns = watchedTxnHashes.size > 0;
```

to:
```typescript
const hasWatchedTxns = watchedTxnHashesRef.current.size > 0;
```

Wait -- actually `watchedTxnHashes` IS in the deps, so it's fine to read it directly. The point is that this check prevents starting the interval when nothing needs polling. Keep line 114 as-is (reading `watchedTxnHashes` directly is fine since it's in deps and drives the effect lifecycle).
