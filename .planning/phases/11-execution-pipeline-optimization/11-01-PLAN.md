<objective>
Eliminate the 2-8 second per-execution oracle price update overhead by implementing proactive background price updates and conditional freshness checks.

Purpose: The current execution pipeline calls `updatePriceOnChain()` synchronously before every deposit/withdrawal/order execution, adding 2-8 seconds of blocking wait for the oracle TX to be mined. By moving oracle updates to a background loop triggered by Pyth Lazer WebSocket messages, the on-chain stored prices stay perpetually fresh. At execution time, a single `readContract` freshness check (~50ms) replaces the full TX submission + receipt wait.

Output: Modified `pythLazerOracle.ts` with background updater, modified `baseExecutor.ts` with conditional oracle update, and modified `index.ts` with nonce coordination between background updater and execution queue.
</objective>

   - Before each execution (after dequeue, before the if/else block), disable background updates:
     ```typescript
     const pythLazerOracle = getPythLazerOracle();
     if (pythLazerOracle) {
       pythLazerOracle.disableBackgroundUpdates();
       // Wait briefly if a background update is in-flight
       let waitCount = 0;
       while (pythLazerOracle.isBackgroundUpdateBusy() && waitCount < 50) {
         await new Promise((r) => setTimeout(r, 100));
         waitCount++;
       }
     }
     ```
   - After each execution completes (in the try block after `recordExecution`, and also in the catch block after `queue.fail`), re-enable:
     ```typescript
     if (pythLazerOracle) {
       pythLazerOracle.enableBackgroundUpdates();
     }
     ```
   - Use a finally block or ensure both try and catch paths re-enable. The cleanest pattern:
     ```typescript
     const oracleService = getPythLazerOracle();
     try {
       if (oracleService) oracleService.disableBackgroundUpdates();
       // ... wait for busy ...
       // ... execute ...
       queue.complete(item.key);
       recordExecution(item.type);
     } catch (error) {
       queue.fail(item.key);
       log.error(...);
     } finally {
       if (oracleService) oracleService.enableBackgroundUpdates();
     }
     ```

4. In the shutdown sequence, disable background updates before stopping:
   ```typescript
   const pythLazerOracleForShutdown = getPythLazerOracle();
   if (pythLazerOracleForShutdown) {
     pythLazerOracleForShutdown.disableBackgroundUpdates();
   }
   ```

**Nonce coordination rationale (from research):** The keeper uses a single wallet. The background updater sends `updatePrice` TXs. The executor sends `executeDeposit`/`executeWithdrawal`/`executeOrder` TXs. If both send at the same time, they race for the same nonce. The simplest coordination: disable background updates during the execution window. The drain loop's 100ms idle wait means the pause is brief when no queue items exist.
