    The config system works by merging: per-market values override defaults from `baseMarketConfig` (line 554). The `baseMarketConfig` already has sensible values for fees, borrowing, funding, and min collateral. What's MISSING from `baseMarketConfig` are the capacity/limits fields:
    - `maxLongTokenPoolAmount`

    - `maxPoolUsdForDeposit`
    - `maxOpenInterest` (or `maxOpenInterestForLongs`/`maxOpenInterestForShorts`)

    Per user decision: per-type tuning with realistic production-like params.

    **Crypto markets (WETH, WBTC):**
    Use `baseMarketConfig` defaults (already reasonable) plus:
    ```typescript
    {
      tokens: { indexToken: "WETH", longToken: "USDC", shortToken: "USDC" },
      reversed: false,
      maxLongTokenPoolAmount: expandDecimals(1_000_000, 6),    // 1M USDC (6 decimals)
      maxShortTokenPoolAmount: expandDecimals(1_000_000, 6),   // 1M USDC
      maxPoolUsdForDeposit: decimalToFloat(1_000_000),         // 1M USD
      maxOpenInterestForLongs: decimalToFloat(500_000),        // 500K USD
      maxOpenInterestForShorts: decimalToFloat(500_000),       // 500K USD
    }
    ```
    Same pattern for WBTC.

    **Forex markets (EUR, GBP, JPY):**
    Use `syntheticMarketConfig` spread (since these are synthetic) plus:
    ```typescript
    {
      tokens: { indexToken: "EUR", longToken: "USDC", shortToken: "USDC" },
      reversed: false,
      ...syntheticMarketConfig,
      maxLongTokenPoolAmount: expandDecimals(500_000, 6),      // 500K USDC
      maxShortTokenPoolAmount: expandDecimals(500_000, 6),     // 500K USDC
      maxPoolUsdForDeposit: decimalToFloat(500_000),           // 500K USD
      maxOpenInterestForLongs: decimalToFloat(250_000),        // 250K USD
      maxOpenInterestForShorts: decimalToFloat(250_000),       // 250K USD
    }
    ```
    Same pattern for GBP. JPY has `reversed: true` — keep that.

    **Commodity market (GOLD):**
    Use `syntheticMarketConfig` spread plus slightly higher limits (gold is popular):
    ```typescript
    {
      tokens: { indexToken: "GOLD", longToken: "USDC", shortToken: "USDC" },
      reversed: false,
      ...syntheticMarketConfig,
      maxLongTokenPoolAmount: expandDecimals(750_000, 6),      // 750K USDC
      maxShortTokenPoolAmount: expandDecimals(750_000, 6),     // 750K USDC
      maxPoolUsdForDeposit: decimalToFloat(750_000),           // 750K USD
      maxOpenInterestForLongs: decimalToFloat(375_000),        // 375K USD
      maxOpenInterestForShorts: decimalToFloat(375_000),       // 375K USD
    }
    ```

    IMPORTANT: USDC on Base Sepolia has 6 decimals. Use `expandDecimals(amount, 6)` for token amounts. Use `decimalToFloat(amount)` for USD-denominated values (30 decimal precision). Check that `expandDecimals` and `decimalToFloat` are imported from `../utils/math` (they should already be at the top of the file).

    NOTE: The `syntheticMarketConfig` object (line ~338) already exists in the file and provides appropriate overrides for reserve factors, PnL factors, and liquidation fees for synthetic markets. Spread it into the forex/commodity configs.

    Also ensure `fundingRateConfig_Default` values are applied to crypto markets and `fundingRateConfig_SingleToken` to synthetic markets. Check if the baseMarketConfig already includes these or if they need to be spread. Looking at the file, `baseMarketConfig` already includes funding config inline. The `syntheticMarketConfig` extends `baseMarketConfig`. So spreading `syntheticMarketConfig` for forex/commodity markets should be sufficient.
