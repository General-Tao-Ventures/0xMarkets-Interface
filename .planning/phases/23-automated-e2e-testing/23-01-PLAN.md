**e2e/config.ts:**

**e2e/abis.ts:**
- ExchangeRouter ABI: `multicall(bytes[])`, `sendWnt(address,uint256)`, `sendTokens(address,address,uint256)`, `createDeposit(params)`, `createWithdrawal(params)`, `createOrder(params)`
- EventEmitter ABI: `EventLog1` event (same as keeper's abis.ts)
- ERC20 ABI: `approve`, `allowance`, `balanceOf`, `mint` (mUSDC is MintableToken)
- Keep ABIs minimal -- only include functions/events actually called by tests
- Use `as const` for all ABIs (viem type inference)

**e2e/helpers.ts:**
- `ensureApprovals(walletClient, publicClient, routerAddress)`: Check USDC and WETH allowances against Router contract, approve max uint if needed. Also mint 500 USDC if balance < 200 USDC (mUSDC has public `mint`).
- `waitForExecution(publicClient, eventEmitterAddress, operationKey, opType, timeoutMs = 60_000)`: Poll `getLogs` on EventEmitter for EventLog1 events where topic1 matches the operation key and eventName matches `{OpType}Executed` or `{OpType}Cancelled`. Poll every 2 seconds. Return `{ status: "executed" | "cancelled" | "timeout", blockNumber?, txHash? }`. This is the CORE verification mechanism -- it proves the keeper detected and executed the operation.
- `extractOperationKey(receipt, eventEmitterAddress)`: Parse transaction receipt logs to find the EventLog1 with eventName=`DepositCreated`/`WithdrawalCreated`/`OrderCreated` and extract topic1 (the operation key bytes32). This key is needed to poll for execution.
- `formatResults(results)`: Print a clean summary table and return exit code (0 if all pass, 1 if any fail).

IMPORTANT implementation details for `waitForExecution`:
- Use `publicClient.getLogs()` with the EventEmitter address and EventLog1 event signature
- Filter by `fromBlock` (the block of the submission tx) to avoid scanning old blocks
- The eventName is NOT indexed -- it's in the event data, so you must decode each log's data to check `eventName`
- Match `topic1` to the operation key (topic1 IS indexed, so filter by it as a topic)
- Detection events: "DepositExecuted", "WithdrawalExecuted", "OrderExecuted" (success) or "DepositCancelled", "WithdrawalCancelled", "OrderCancelled" (failure -- still means keeper detected it)

IMPORTANT for `extractOperationKey`:
- The submission tx emits EventLog1 with eventName="DepositCreated" (or WithdrawalCreated, OrderCreated)
- The operation key is in `topic1` of that event
- Parse the receipt logs: find the log from EventEmitter address, decode as EventLog1, check eventName contains "Created", extract topic1

Create `e2e/test-deposits.ts` that tests deposit execution for all 6 markets.

**Flow per market:**
1. Log market name and address
2. Build deposit params (same structure as existing testAllMarkets.ts):
   - receiver: wallet address
   - market: market address
   - initialLongToken: USDC, initialShortToken: USDC
   - Send 10 USDC as longToken + 10 USDC as shortToken (20 USDC total per deposit)
   - executionFee: 0.001 ETH
   - callbackContract: zeroAddress, callbackGasLimit: 0, minMarketTokens: 0
3. Build multicall args: `[sendWnt(depositVault, execFee), sendTokens(usdc, depositVault, 10e6), sendTokens(usdc, depositVault, 10e6), createDeposit(params)]`
4. Submit tx via walletClient, wait for receipt
5. Extract operation key from receipt using `extractOperationKey`
6. Call `waitForExecution(publicClient, eventEmitter, key, "Deposit", 60000)`
7. Record result: PASS if executed, FAIL if cancelled or timeout

**Script structure:**
```typescript
async function main() {
  // Ensure approvals + USDC balance
  await ensureApprovals(...)

  const results = [];
  for (const [name, market] of Object.entries(MARKETS)) {
    const result = await testDeposit(name, market);
    results.push(result);
    // 3-second delay between markets to avoid nonce issues
    await sleep(3000);
  }

  formatResults(results);
  process.exit(results.every(r => r.status === "PASS") ? 0 : 1);
}
```

**Error handling:** Wrap each market's test in try/catch. If the submission tx itself reverts, record as FAIL with the revert reason. If waitForExecution times out after 60s, record as FAIL with "Keeper did not execute within 60s".
