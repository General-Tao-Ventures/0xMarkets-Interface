<objective>
Eliminate redundant on-chain reads by passing operation data from scanners through the execution queue to executors.

Purpose: Each executor currently re-reads the full deposit/withdrawal/order struct and market data from on-chain, even though the scanner already fetched this data during detection. This adds ~300-500ms of redundant RPC calls per execution. By extending the queue to carry optional operation data, poll-sourced items include pre-fetched data that executors can use directly. Event-sourced items (which only know the key) gracefully fall back to chain reads.

Output: Extended `QueueItem` with `operationData`, modified scanners to attach data, modified executors to use pre-fetched data, and wired `index.ts` to pass data through the pipeline.
</objective>
