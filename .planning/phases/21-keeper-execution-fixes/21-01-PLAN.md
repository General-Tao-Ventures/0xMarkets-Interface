**Step 3: Diagnose and fix each failure**

For EACH revert/error, diagnose the root cause. The most likely failure modes are:

**A. Oracle price errors (OracleTimestampsAreSmallerThanRequired, MaxPriceAgeExceeded):**
- The contract's `withOraclePrices` modifier calls `oracle.setPrices(oracleParams)` which calls `_validatePrices`.
- `_validatePrices` checks: `validatedPrice.timestamp + maxPriceAge >= Chain.currentTimestamp()`
- If the Pyth Lazer data is >300s old (MAX_ORACLE_PRICE_AGE on-chain), the TX reverts.
- Fix: Ensure `CACHE_TTL_MS` in oracle.ts is less than the on-chain `MAX_ORACLE_PRICE_AGE`. Current value is 270s with 30s margin -- this should be fine. If prices ARE too old, check Pyth Lazer subscription is working and `handleMessage` is receiving updates.

**B. InvalidOracleProviderForToken (provider != expectedProvider):**
- `_validatePrices` checks: `dataStore.getAddress(Keys.oracleProviderForTokenKey(token)) == provider`
- The keeper sends `config.pythLazerFeedProviderAddress` as the provider for ALL tokens.
- If a token's on-chain oracle provider is different (e.g., set to Hermes provider), this reverts.
- Fix: Read each token's configured provider from DataStore and use token-specific providers in `buildOracleParams`. Or verify all tokens use the Pyth Lazer provider on-chain.
- Check on-chain: For each token, read `DataStore.getAddress(Keys.oracleProviderForTokenKey(tokenAddress))` and compare with `PYTH_LAZER_FEED_PROVIDER_ADDRESS`.

**C. Unauthorized / onlyOrderKeeper:**
- Keeper wallet needs ORDER_KEEPER role. Fixed in Step 1.

**D. EmptyPrimaryPrice:**
- The contract needs prices for tokens the keeper didn't include in oracleParams.
- For deposits: index token + collateral tokens with non-zero amounts
- For withdrawals: index token + long token + short token
- For orders: index token + initial collateral token
- Since all markets use USDC as both long and short token, deposits need prices for USDC + index token, withdrawals need USDC + index token, orders need USDC + index token.
- Fix: Verify that `getDepositTokens`, `getWithdrawalTokens`, `getOrderTokens` in executor.ts return all required tokens.

**E. InsufficientExecutionGas / out of gas:**
- `GasUtils.validateExecutionGas` checks that `gasleft()` exceeds estimated gas limit.
- If `GAS_LIMIT = 8_000_000n` is too low, the TX runs out of gas before reaching the execution logic.
- Fix: Increase `GAS_LIMIT` if gas-related reverts are observed.

**F. Nonce errors after rapid submissions:**
- Multiple operations arriving quickly can cause nonce collisions.
- The executor already handles nonce correction. If issues persist, add a brief delay between TX submissions.
