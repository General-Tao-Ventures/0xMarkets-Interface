## Unsatisfied Requirements Detail

### LIQ-03: Liquidation executor successfully calls executeLiquidation on a real test position

**Requirement:** The executor submits `executeLiquidation` and the transaction succeeds on-chain (visible on Basescan).

**What exists:** Executor code is complete and structurally correct. `writeContract({ functionName: "executeLiquidation" })` is present in executor.ts lines 195-205. Gas estimation gate works correctly (rejects PositionShouldNotBeLiquidated). Receipt watcher (Phase 26) will track the result.

**What's missing:** A successful on-chain transaction hash. The executor has never submitted a real `executeLiquidation` call because no position passed the gas estimation gate during any test session.

**Root cause:** WETH/USD pool reserve saturation on Base Sepolia testnet. Pool has $1,548 USDC with $1,370 already reserved (95% factor = $1,471 max). Only ~$101 headroom blocks creation of new positions that could become liquidatable.

**Path to close:** Inject >$5,000 USDC into WETH/USD pool via Buy GM flow, create a high-leverage position, wait for (or induce via collateral withdrawal) undercollateralization, observe executor TX on Basescan.

### LIQ-04: Confirmator records liquidation result in PostgreSQL with correct status

**Requirement:** The confirmator updates the PostgreSQL record from SUBMITTED to EXECUTED with the correct transaction hash.

**What exists:** Confirmator watches for `OrderExecuted` events with `orderType=7`. `updateExecutionStatus("MINED")` and `updateCandidateStatus("EXECUTED")` are wired in confirmator.ts lines 135-144.

**What's missing:** At least one `liquidation_execution` row with `status=MINED` and a valid `tx_hash` in PostgreSQL.

**Root cause:** Depends on LIQ-03. No liquidation TX was submitted, so no event was emitted.

**Path to close:** Resolve LIQ-03 first. The confirmator will automatically update DB status when the executor's TX is mined.
